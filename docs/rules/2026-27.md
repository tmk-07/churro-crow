# Churro Crow On-Sets Rules Contract

Ruleset ID: `agloa-2026-27`

Status: Phase 1 product contract

This document defines the behavior Churro Crow will test and implement. The core
set logic is stable, while tournament presets and variations are versioned so a
future rules update does not silently change saved problems.

Primary references:

- [AGLOA On-Sets Tournament Rules 2026-27](https://agloa.org/wp-content/uploads/On-SetsRules2627.pdf)
- [Manual for Equations and On-Sets Judges](https://docs.google.com/document/d/1eYNPR2n3_Ab2T6AD_jxDD3Cxay-Q7tG1nwAqaszpKAI/edit?usp=sharing)

## Product boundary

Churro Crow is a private solution checker, solver, and practice tool. It does not
simulate player turns, scoring, penalties, or complete matches.

The solver models three real solution-writing situations:

- **Now:** use every cube in Required, any cubes in Permitted, and at most one
  cube from Resources for each Solution.
- **Impossible:** determine whether a Solution can be written using every cube
  in Required and any cubes in Permitted and Resources.
- **Forceout:** the last Resource cube has moved to Required or Permitted, so the
  Solution uses Required and any cubes in Permitted with no Resources remaining.

The first release accepts a numeric Goal. Goal-cube layouts and Absolute Value
interpretations are deferred until the corresponding variation is implemented.

## Division and universe

The interface provides Elementary, Middle, Junior, Senior, and Custom Practice
presets. Division selection belongs in a persistent, low-distraction control.

Users may select any number of the 16 unique physical cards in every mode. The
app warns, but does not block, when the selected Universe is outside the
tournament range:

The checker presents those cards as the physical 4-by-4 On-Sets chart so a user
can include or exclude a card directly from its familiar position. The solver
may use a denser selection control while its interface is still being reviewed.

| Division | Tournament Universe size |
| --- | ---: |
| Elementary | 6-12 |
| Middle | 6-12 |
| Junior | 6-12 |
| Senior | 10-14 |

Junior and Senior presets automatically enable Multiple Operations, Union and
Intersection Interchangeable, and Universe and Null Interchangeable. A division
preset removes variations that are unavailable in that division. Custom
Practice can expose individual variations without division restrictions.

## Standard notation

The UI displays one notation consistently:

| Meaning | Display |
| --- | --- |
| Colors | `B`, `R`, `G`, `Y` |
| Universe | `V` |
| Null set | `Z` |
| Union | `U` |
| Intersection | `∩` |
| Set subtraction | `−` |
| Complement | `'` |
| Subset restriction | `⊂` |
| Equality restriction | `=` |

Input may also accept keyboard aliases and normalize them before validation:
`u`/`∪` for union, `n` for intersection, `-` for subtraction, `/\`/`∅` for the
null set, and `c`/`C` for the subset restriction. Parentheses, brackets, and
braces are accepted as grouping symbols and displayed as parentheses.

## Expression interpretation

1. Explicit grouping symbols are applied first.
2. Complement applies to the immediately preceding set or grouped expression
   and takes priority over every binary operation.
3. Union, intersection, subtraction, and any special binary operation have no
   relative precedence.
4. An ungrouped expression with multiple binary operations has every grouping
   permitted by its existing grouping symbols as a legal interpretation.
5. The checker lists every legal interpretation in fully parenthesized form,
   together with its resulting physical cards and card count. Results are
   sorted by value and grouped under one selectable value tab per distinct
   result.
6. The checker reports the actual value of every interpretation without asking
   for a Goal. A tournament Solution is correct only when every reported value
   equals the separately declared Goal.
7. The solver should generate minimally ambiguous answers. It should add
   grouping whenever omitting it could create a different result.

The expression-evaluation checker reports results and interpretations; it does
not reject an expression merely because it uses fewer than two cubes. Tournament
solution validation is a separate concern.

## Set-Names and restrictions

A complete Solution contains one Set-Name and, when required or chosen, one or
more Restrictions.

- Subset Restriction: `A ⊂ B` removes cards that are in `A` but not `B`.
- Equals Restriction: `A = B` removes cards that are in exactly one of `A` and
  `B`.
- Chain Restriction: consecutive restriction operators apply to adjacent
  Set-Names, such as `A ⊂ B = C` meaning `A ⊂ B` and `B = C`.
- Multiple independent Restrictions all filter the same Solution's Universe and
  may be applied in any order.
- Grouping may occur inside a Set-Name on either side of a restriction operator.
  Grouping may not enclose only part of a chain or otherwise treat a restriction
  statement as a Set-Name.
- Restrictions are applied before the Solution's Set-Name is evaluated.

## Cube inventory

- Every physical cube in Required must be used.
- No physical cube in Forbidden may be used.
- Any subset of Permitted cubes may be used.
- Symbol counts matter because multiple physical cubes can show the same symbol.
- A complete tournament Solution contains at least two cubes across its
  Restriction and Set-Name parts.
- If `⊂` or `=` is in Required, a Restriction is mandatory.
- Variation declaration checks inspect the complete current cube state, so a
  required `⊂` or `=` cube counts as available even when Resources contains no
  Restriction cube.
- If any Restriction is written, every Required cube is used in its Restriction
  part. Every Required cube except `⊂` and `=` is also used in the Set-Name.
- The same physical Required and Permitted inventory is independently available
  to the Restriction and Set-Name. Reusing a cube symbol in both parts does not
  require a duplicate physical cube.
- An optional Restriction follows the same Required-cube rule as a mandatory
  Restriction.

## Variation behavior locked for the rebuilt checker and solver

### No Null Restrictions

- This variation does not require a Restriction.
- Every independent Restriction that is written must remove at least one card
  from the Universe regardless of application order.
- A chain Restriction satisfies the variation when at least one link of the
  chain removes a card.

### Result diversity (product behavior)

The official Two Solutions variation is not a selectable product option. The
solver normally produces multiple independent Solutions and groups them by the
physical card set they contain. It promotes one Solution from each distinct card
set before showing alternate expressions for a previously shown set. The UI
must make clear that two expressions in the same group name the same physical
cards and therefore are not distinct card sets.

This ordering is a discovery aid, not validation of the official Two Solutions
variation.

### Multiple and Two Operations

- With Multiple Operations, an operation cube not in Forbidden may be used more
  than once. Required operation cubes must still all be accounted for.
- Junior and Senior enable Multiple Operations automatically.
- With Two Operations, the Set-Name contains at least two operation symbols;
  the two symbols need not be different.

### Interchangeable cubes

- With Union and Intersection Interchangeable, each physical `U` or `∩` cube
  may independently be written as either mathematical operation.
- With Universe and Null Interchangeable, each physical `V` or `Z` cube may
  independently be written as either Set-Name.
- Junior and Senior enable both rules automatically.

### Wild Cube

- One specific physical cube is selected as wild. Its identity is retained as
  its current section, shown face, and occurrence number, so another cube with
  the same face is not also wild.
- The selected physical cube may represent any nondigit cube symbol.
- Its interpretation is consistent throughout a single complete Solution,
  including its Restriction and Set-Name.
- The same selected cube may be reused between the Restriction and Set-Name,
  subject to the normal complete-Solution cube-reuse rules.
- The solver may choose the interpretation and reports it with the result.
- Wild Cube is not shown in the expression Checker because that page receives
  already-written mathematical notation rather than a physical cube state.
- `⊂` and `=` may not be selected as wild outside Elementary.

### Blank Card Wild

- The blank physical card may be assigned any subset of the four colors for one
  Solution.
- The checker accepts a specified assignment. The solver may search all 16
  assignments inside one shared time budget and reports the assignment used.
- Changing the blank card's dots never changes its physical card identity.
- Double Set and Required/Forbidden Card use the blank card's assigned colors
  where the official rules require them to do so.

### Symmetric Difference

When active, `A − B` means `(A − B) U (B − A)`, where the two inner subtraction
signs mean ordinary set subtraction. The selection order of Symmetric Difference
and Double Set determines what `−` means inside the Double Set declaration.

### Double Set and Required/Forbidden Card

The app identifies an illegal variation declaration and explains the issue, but
offers **Proceed anyway** because a declaration that cannot affect the shake can
be useful during private practice.

Official Double Set validation includes a nonempty set that is not the Universe
and a declaration containing no more than four cube symbols, excluding grouping
symbols. Required and Forbidden Card constraints apply to the physical cards in
the final Set-Name.

## Solver result contract

- The requested solution count is an input.
- Results are deterministic and ordered by the shortest/lowest-cube expression
  first.
- Results are grouped by resulting physical card set. One result from every
  available distinct set is promoted before alternate written expressions are
  retained inside those groups.
- The app clearly says when a search stopped at the requested count.
- After returning results, the interface offers to find more.
- Exact Goal equality is required; a result with more cards than the Goal is not
  a Solution.
- The solver tries a Set-Name without a Restriction, then one regular or chain
  Restriction when needed. Multiple independent Restrictions are searched only
  as a reserve strategy when those regular searches find no Solution.
- When an Impossible search finds no answer, the product reports only that
  nothing was found.

## Checker interface contract

- Checker inputs are the Division, Universe, expression-relevant variations,
  optional Restriction statements, and optional Set-Name.
- The Checker does not request a Goal or physical shake-cube inventory.
- Cube-identity-only variations such as Wild Cube, Multiple Operations, and the
  interchangeable-cube declarations belong to the Solver and are omitted from
  the Checker.

## Phase 1 test sources

Golden tests begin with examples from the official tournament rules and judges'
manual. A later practice set will present custom Universes, expressions, and
variations for a human answer key before those examples become additional golden
tests.
